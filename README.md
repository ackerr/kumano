# 熊野古道 · 中边路 41 章攻略与地图

静态网页，中文界面，保留日文地点名。Leaflet 1.9.4 已本地化，无需安装生产依赖、地图密钥或数据库。

```sh
npm run dev
npm test
```

本机打开 http://127.0.0.1:4317 。手机远程访问必须使用 HTTPS；普通局域网 HTTP 不支持浏览器定位。

首页为 5 天 4 晚的 41 章紧凑规划，允许公交替代徒步，必要时预约车辆。四晚依次为野中、汤峰、小口、那智山，Day 5 从新宫离开；Day 0 田边前夜另计，合计五晚。Day 1、2、4 为长日。41章已完整分配，但 Day 1 西部可达下车点和 Day 3 川舟中心访问／车辆尚待确认，不是已验证可照走的行程。

地图在 `map.html`：对照官方图的真实路线与分支（可开关、按段查看来源）、41 个官方编号点位、浏览器实时定位与精度圆、按直线距离排序的附近盖章点、地图中心 3 km 内厕所/饮水服务/补给分类、每个点位的来源与坐标说明。攻略的章点和补给入口可直接跳转地图，并返回对应 Day。

编辑 `guide-data.mjs` 后运行 `npm run build` 生成 `dist/index.html`；正文无须 JavaScript 即可阅读。`npm run dev` 会先构建再启动预览，`npm test` 也会先构建，支持新检出的仓库。编排依据、来源冲突和访问缺口见 [docs/guide-evidence.md](docs/guide-evidence.md)。

## 资料与限制

- 清单基准：[和歌山县官方41章地图](https://www.wakayama-kanko.or.jp/lsc/upfile/articleDetail/0000/2510/2510_d003_file.pdf)。JSON 的 `sourceUrl` 指向清单，`coordinateSourceUrl` 指向坐标证据。
- 41处全部有可追溯的参考坐标，并非41个章箱的实测坐标。官方景点、官方街景拍摄位置、社区地图地点不能混同；`coordinateNote` 保留区别。第28高野坂已交叉检查公众押印点与官方路线北端约8m距离。
- 设施来自 [WAKAYAMA800](https://wakayama800.jp/facilities-page/catid5/) 的厕所/骑行站公开目录及设施官网：77厕所、21饮水服务、4补给分类条目。同一设施可提供多种服务，因此不是102个独立场所，也不是沿线完整清单。
- 饮水是设施公布的服务，不保证户外自助或随时开放。页面提示向工作人员询问。
- 五天方案及本轮路线／交通核对日2026-10-10，住宿来源核对日2026-10-09；地图点位与设施沿用2026-10-03核验版本，OSM底库日期2026-07-24。不是现场巡检日期。不自动声称设施当前开放。
- 住宿候选不代表实时有房；具体班次、天黑时间、旅宿接驳与章箱访问条件需按出发日期复核。第24章川舟中心在冬季、停航日或仅盖章时是否可访问仍需电话确认。Day 2 若从发心门乘车直达本宫，会漏掉第18、19章，不得当作当日41章任务完成的备用方案。
- 地图范围限制在和歌山一带的纪伊半岛，默认总览中边路。范围外定位只用于距离排序，不切换世界地图。
- 国土地理院瓦片在线加载；本站未提供离线地图。没有把盖章点用直线连接成假步道，没有提供山路逐步导航。攻略步行时间来自注明的官方区间或明确标记的编排估算。
- GPS不发送到本站或保存。地图提供商会收到浏览区域的瓦片请求；外链在点击后交由目标网站处理。
- 路线数据为 `dist/routes.geojson`，18组、210个独立原始段、7,779个坐标，含11条县官方合作YAMAP课程、6处路网连接和1条舟运参考线。详见 [ROUTES.md](ROUTES.md)。已排除2025年停用的岩神南侧绕行，不将章点按编号直连。
- 资料数据在 `dist/stamps.json`、`dist/amenities.json`、`dist/routes.geojson`；修改后运行 `npm test`。

## 验证

`npm test` 检查全部坐标来源、41点完整性、设施分类和距离边界，以及攻略41章各安排一次、每日引用、四晚当地住宿＋一晚抵达住宿、长日及必要接驳缺口。`qa.mjs` 使用 Playwright 浏览器验证攻略逐日跳转、章点与设施地图链接、返回与浏览器后退、桌面及390/320px布局，以及定位成功/移动/陈旧/拒绝、设施过滤、页面恢复、路线开关、分段来源与路线载入失败。它只模拟GPS，不替代山中手机实测。

已有 Playwright 时运行 `npm run test:browser`；可用 `PLAYWRIGHT_MODULE` 指定已安装模块，`CHROMIUM_PATH` 指定已有浏览器，`PREVIEW_URL` 指定预览地址。截图输出 `qa/`，不发布。WebMCP为可选增强：在无原生支持环境测试使用模拟注册器；界面不依赖它。

## 发布

GitHub Pages 自动发布配置见 `.github/workflows/pages.yml`：推送到 `main` 或手动运行工作流后，使用 Node.js 24 执行 `npm test`（含构建），校验成功才上传 `dist/` 并部署。项目无 npm 依赖，因此无需 `npm install` 或依赖缓存。

首次启用须在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。个人仓库发布的 Pages 网站可被公众访问，即使源码仓库是私有的；启用前需确认符合访问范围要求。默认项目地址为 `https://ackerr.github.io/kumano/`，只有部署成功后才可用。在 Actions 查看 `Deploy GitHub Pages` 的运行结果；仅在本地 commit 不会触发，必须 push 到 GitHub。

运行 `npm run build` 后，`dist/` 是完整静态输出。现有本机的 Sites 项目身份保存在 `.openai/hosting.json`，该配置不纳入 Git；新检出需要单独配置发布目标。当前交付为本机预览，未确认线上部署成功；手机远程定位必须部署在HTTPS。Leaflet许可证保留于 `dist/vendor/LEAFLET-LICENSE.txt`，OSM来源署名与国土地理院署名保留在页面。
